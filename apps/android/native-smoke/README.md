# Android native core smoke

This small Android application packages the existing `libscpefe` C ABI and a
JNI byte-array adapter in one shared library. It has no user-facing activity; the
real WebView integration belongs to later Android issues. The adapter keeps one C context per opaque
Java handle, returns the C ABI status codes, and closes the context and active
container on `nativeCloseContext`. Password and content copies in native memory
are erased before each JNI call returns. Java owns returned cleartext arrays and
must erase them after use. Calls are synchronous and belong off the UI thread.

`AndroidDocumentTargets` provides SAF create/open picker intents and retains only
the granted read/write permissions needed for later operations. It returns random
opaque keys; provider URIs stay in app-private target metadata. `read` rereads
complete bytes, bounded by the core's 33 MiB container limit. `publish` compares
the current complete image with the authenticated base, attempts a provider write
only when the grant and document flags permit it, and reports verified only after
an exact-byte reread. A provider write is **best effort**, not an atomic replace or
compare-and-swap. The host must journal the candidate before calling it and keep
that candidate for any ambiguous result, including a partial write or lost read
permission. Provider display names, timestamps, sizes, and revision tokens are
never used as authenticated freshness evidence. The instrumented test APK includes
a local document provider for emulator I/O tests; release builds omit it. Generic
SAF deletion lacks compare-and-delete, so `removeCreated` explicitly reports
unsupported cleanup and leaves a matching created document intact rather than
risking deletion of a concurrent update.

`AndroidProfileSettings` persists the existing `{name,email,deviceName}` profile
and regular-save settings JSON shapes in app-private storage, validating the same
field bounds and defaults as the shared frontend contract. `AndroidWorkJournals`
stores the same version-1 AES-GCM journal envelope used by Windows, with the
core-derived 32-byte journal key returned by `nativeJournalKey`. Callers must
erase that Java byte array after use. Exact candidate bytes and publication
metadata remain inside the authenticated ciphertext; the envelope's optional
bootstrap holds only the already encrypted base container and a target hash.
The journal is keyed by authenticated document ID and rejects a different opaque
target. `AndroidHeadWitnesses` MACs client-local revision observations and
returns structured rollback, divergence, replacement, or unreadable attention.
Private records use a synced temporary file and atomic replacement. A failed
write keeps the previous record, and unreadable journals remain on disk for
explicit recovery decisions. The application manifest sets `allowBackup=false`
so app-private profile, settings, grants, journals, witness key, and witness
records are excluded from Android cloud backup.

## Pinned toolchain and clean build

- JDK 17, Android Gradle Plugin 8.11.1, Gradle 8.13.
- Android SDK API 35, build tools 35.0.0, NDK 27.3.13750724 (r27d).
- libsodium 1.0.20 source archive, SHA-256
  `ebb65ef6ca439333c2bb41a0c1990587288da07f6c7fd07cb3a18cc18d30ce19`.
  `scripts/build-android-native.sh` builds the full static sodium library for
  each target ABI and links it into the existing shared core. The original
  download and build instructions are at
  <https://doc.libsodium.org/installation>.

From the repository root, with `ANDROID_HOME` and `ANDROID_NDK_HOME` set:

```sh
bash scripts/build-android-native.sh x86_64 arm64-v8a
gradle -p apps/android/native-smoke --no-daemon assembleDebugAndroidTest
gradle -p apps/android/native-smoke --no-daemon connectedDebugAndroidTest
```

The last command requires a running API 35 emulator. The CI job uses the
preinstalled Android SDK, NDK, and accepted licences on the Ubuntu runner,
builds from a clean checkout, starts an x86_64 emulator, and executes the
instrumented test. It does not accept new SDK licences; missing acceptance
fails the job.
The test consumes the same revised-v3 baseline vector used by the native
conformance suite: document ID `101112131415161718191a1b1c1d1e1f`, content
`alpha\n`, and password `correct horse battery staple`. It checks malformed
input and wrong-password statuses and repeats create/open/close operations.
The fixture is generated by the repository's deterministic format generator;
its provenance is documented in `tests/vectors/draft-v3/README.md`.

The CI Windows job also creates a fresh revised-v3 document through the Windows
build of the C ABI and uploads its encrypted bytes and authenticated document
ID to the Android job. The Android instrumented test opens those exact bytes,
authenticates, and compares the document ID and content. To run that test by
hand, first build `scpefe_android_fixture_writer` on Windows with
`SCPEFE_BUILD_ANDROID_FIXTURE_WRITER=ON`; put its two outputs in
`app/src/androidTest/assets/windows/`.

The packaged APK assets contain the SCPEFE, libsodium, and zxcvbn-c licence
notices. Build output, downloaded source, and generated notices are ignored by
Git. The repository `LICENSE` and `third_party/zxcvbn-c/LICENSE.txt` remain the
maintained source notices.
