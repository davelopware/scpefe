# Android WebView insets and mobile sizing

Researched 2026-11-12 for the Capacitor Android preview. This is implementation guidance, not an emulator result.

## Current state

The preview uses Capacitor 7.6.10 and targets SDK 35 (`apps/android/web/package.json`, `apps/android/web/android/variables.gradle`). Its Capacitor config has no Android inset setting, its viewport tag specifies `width=device-width, initial-scale=1.0` without `viewport-fit=cover`, and its WebView imports the shared Windows stylesheet (`apps/android/web/capacitor.config.json`, `apps/android/web/index.html`, `apps/android/web/src/main.tsx`). That stylesheet has a 14 px root font, a 2.25 rem menu bar, a 1.8 rem status bar, 2 rem dialog close controls, and 36 px CSV table rows (`apps/windows/src/styles.css`). These are code observations, not measured Android tap areas.

## Platform and library findings

- Android 15 and later display an SDK 35 app edge to edge: the window extends behind the status bar, navigation bar, and cutouts. Interactive controls need system-bar and cutout insets so the bars do not cover them. Gesture navigation has a transparent navigation bar; three-button navigation has a translucent scrim by default. [Android edge-to-edge views guidance](https://developer.android.com/develop/ui/views/layout/edge-to-edge), [Android 15 behavior changes](https://developer.android.com/about/versions/15/behavior-changes-15).
- Android 16 removes `windowOptOutEdgeToEdgeEnforcement` for an app targeting SDK 36 **on an Android 16 device**. This preview still targets SDK 35, but an opt-out is a poor long-term plan. [Android 16 behavior changes](https://developer.android.com/about/versions/16/behavior-changes-16).
- Capacitor 7's `android.adjustMarginsForEdgeToEdge` has `disable` as its documented default. `auto` adjusts WebView margins on Android 15+ when the theme has not opted out; `force` always adjusts them. The app currently leaves the setting at its default. Capacitor 7's Status Bar `overlaysWebView` option does not remove Android 15 overlap unless the platform opt-out is set. [Capacitor 7 configuration](https://capacitorjs.com/docs/v7/config), [Capacitor 7 Status Bar](https://capacitorjs.com/docs/v7/apis/status-bar).
- WebView exposes system-bar and cutout safe areas to CSS only for fullscreen WebViews from M136, and for all WebViews from M144. Keyboard-related visual viewport resizing starts at M139. Thus `env(safe-area-inset-*)` alone is not a reliable fallback for every WebView version the app can run on. [Android WebView inset compatibility](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets).
- Native padding and web safe-area padding can double-count the same inset. When native code handles an inset, Android's WebView guidance prefers zeroing that handled type before forwarding insets, rather than switching to `WindowInsetsCompat.CONSUMED` after previously forwarding nonzero insets; the latter can leave stale keyboard padding. [Android WebView inset handling](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets).
- Android recommends touch targets of at least 48 dp and body text no smaller than 12 sp, with scalable text. For WebView, CSS pixels are converted approximately to density-independent pixels when the mobile viewport is configured; web guidance recommends about 48 CSS px targets and spacing between adjacent targets. These are sizing guides, not an exact CSS-px-to-sp conversion. [Android accessibility guidance](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility), [Android WebView screen sizing](https://developer.android.com/develop/ui/views/layout/webapps/targeting), [web.dev tap targets](https://web.dev/articles/accessible-tap-targets). Capacitor 7 also offers a Text Zoom API to read and apply the user's preferred WebView text scale. [Capacitor 7 Text Zoom](https://capacitorjs.com/docs/v7/apis/text-zoom).

## Recommendations for this preview

1. **Choose one inset owner.** For a first contained pass on Capacitor 7, trial `android.adjustMarginsForEdgeToEdge: "auto"` so the whole WebView stays outside system bars on Android 15/16, and do not add the same CSS safe-area padding. If the desired design draws the WebView behind the bars, keep native margins disabled, add `viewport-fit=cover`, and place `env(safe-area-inset-*)` padding on the top/bottom interactive chrome; provide a native inset fallback for WebViews before M144. Treat this as an implementation choice to verify on devices, not a claim that either path is already tested. [Capacitor 7 configuration](https://capacitorjs.com/docs/v7/config), [Chrome edge-to-edge migration guide](https://developer.chrome.com/docs/css-ui/edge-to-edge), [Android WebView inset compatibility](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets), [Android edge-to-edge views guidance](https://developer.android.com/develop/ui/views/layout/edge-to-edge).
2. **Size the interactive areas for touch.** Audit the File/Edit/Security/Help triggers, menu items, internal status actions, dialog close button, password visibility button, and CSV cells at roughly 48 CSS px hit areas. A 36 px row or 2 rem control is a candidate for expansion even if its visible icon stays small. Avoid fixed heights that clip enlarged text; check the 14 px root and `.85rem` status text at system large-font settings. Use relative CSS sizing and consider Capacitor Text Zoom if the WebView does not follow the user's preferred scale. [Android accessibility guidance](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility), [web.dev tap targets](https://web.dev/articles/accessible-tap-targets), [Capacitor 7 Text Zoom](https://capacitorjs.com/docs/v7/apis/text-zoom).
3. **Verify on real rendering paths.** Capture Android 15 and 16 screens with gesture and three-button navigation, portrait and landscape/cutout, keyboard open/closed, and enlarged text. Check the menu bar, internal status bar, bottom dialog actions, picker return, text editor caret/scroll, and CSV controls for occlusion, duplicate gaps, and tap size. Include an older WebView if the CSS safe-area path is chosen. This matrix follows the platform's separate system-bar, cutout, gesture, and IME inset behaviors. [Android edge-to-edge views guidance](https://developer.android.com/develop/ui/views/layout/edge-to-edge), [Android WebView inset compatibility](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets).
